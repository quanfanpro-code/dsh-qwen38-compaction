# 首版验收记录

日期：2026-09-09。环境：Windows，Node.js 24.19.0，DSH 0.1.2-rc.1，pi-ai 0.84.4。

## 实际结果

- 原版失败证据：实际 HTTP 请求未包含 enable_thinking=false，断言得到 undefined；未加插件摘要策略时原生摘要预算为 8192。
- 插件定点检查：3 项测试全部通过，退出码 0。覆盖并发请求隔离、目标摘要参数、普通聊天、其他模型、原生自动循环、原生手动压缩、空摘要、截断、服务错误和取消。
- 实际安装包在独立 DSH web 配置中安装并启动成功。
- 本机正式 web 配置安装后，通过原快捷方式重启；运行时插件清单确认 qwen38-compaction-adapter 和 qwen38-compaction-presets 均 active，原入口 disabled，故障组件数量为 0，standard 模式正常且仍为默认。
- 本机先前手改的原适配器和标准模式文件已先备份、再恢复；SHA-256 与新下载的官方固定版本一致。插件不再依赖那两处修改。

## 真实 Qwen 验收

使用合成对话，关键信息仅存在于最早一段、确实被压缩的历史中。保留的近期内容不重复关键事实，避免从近期消息答对却误以为摘要保留成功。

| 场景 | 压缩前估计 tokens | 压缩后估计 tokens | 摘要实际输入／输出 tokens | 压缩及后续问答耗时 |
|---|---:|---:|---|---:|
| 原生循环自动触发 | 102769 | 26347 | 63735／440 | 43.643 秒 |
| 原生手动压缩 | 24769 | 777 | 20816／330 | 22.961 秒 |

两次继续问答均正确保留金额、日期、禁止事项、纠正后的联系人和待办。摘要预算均为 16384。估计上下文数量来自 DSH 原生计量器，不等于服务实际输入数量。

## 审查与修正

- 只改变摘要用途下的模型描述副本；普通请求、共享模型、原凭据解析和通信错误处理沿用原实现。
- 不提供代理或第二个模型接入；原生自动阈值、历史事务与失败保护未重写。
- 构建检查固定版本和精确替换位置，原始来源与版权随制品保留。
- 初次验收脚本错误使用了旧的 Context 释放接口，已按实际 Cordis 接口修正；小上下文测试会触发 SDK 输出预算裁剪，改用真实目标上下文容量。
- 真实手动压缩曾因金额带千分位逗号而被脚本误判；已按数值含义修正并重新运行完整真实验收。
- DSH 包管理器对未批准的依赖构建脚本会报错；安装明确使用 --ignore-scripts，不批准无关构建脚本。

## 范围与限制

此证据不是任意部署、任意长对话或任意 DSH 版本的保证。首版服务标识默认 qwen38，模型 Qwen3.8-27B，标准模式，OpenAI 兼容聊天协议；其他模式和服务的思考参数另行核验。

自定义应用层原适配器配置或模式目录需要先合并，不能盲目覆盖。首版默认插件层使用 DSH 标准 web 配置。

新增 Windows 选包脚本已检查语法；安装包的实际安装命令已执行验证。图形文件选择窗口未用自动化单独操作，不将其记为已做界面测试。

没有发布真实服务地址、凭据、对话、业务文件或完整本机日志。仅公开合成测试和无敏感信息的结果。
