# DSH 与 Qwen3.8 压缩插件方案

状态：用户明确要求立即编写插件、不再停下等待，采用推荐方案 A 连续执行；本文不是已实现或已验收的声明。

## 推荐结论

采用方案 A：把已有有效修补封装成 DSH 官方支持的插件包，继续使用原生压缩流程，只调整 Qwen 摘要请求的思考开关和输出上限。不增加模型接入，不复制用户地址和凭据，不修改 DSH 安装目录。

## 已核实的约束

- 本机目标版本为 DSH 0.1.2-rc.1。正式制品必须以官方发布包为基准，不能把本机修改后的文件当作原版。
- DSH 支持通过 dsh.bundle.patch 装载插件包；应用层配置可以停用原组件并装入替代组件。
- 配置补丁中的 name 是身份校验，不是改名操作；不能用改 name 的方式替换组件。配置块替换也不是逐字段合并，安装前须识别用户自定义块。
- 标准模式在自己的范围内装载压缩组件，应用层新增一个同名服务不能直接替代它。
- 内置标准模式会优先于用户同名模式；要提供同一 standard 标识下的适配配置，必须显式调整模式目录优先级，不能要求旧对话切换模式。
- 原生 BasicCompactionEngine 支持扩展摘要生成，但已有模型适配器没有公开的“按用途修改模型描述”回调。请求中间件不适合偷偷改写既有请求。
- 已有修补的两项变化一起完成过真实手动压缩；并未证明仅改一项就足够。方案保留两项，插件需重新验收自动和手动路径。

## 方案比较

| 方案 | 实现与维护 | 风险、兼容与验证 | 可逆性 |
|---|---|---|---|
| A：原生组件最小派生插件，推荐 | 保留目标版本原适配器代码，仅加入摘要用途分支；原生压缩代码不重写。需跟踪上游版本差异 | 保留原有凭据、流式响应、取消、历史处理；必须锁定版本并检查普通聊天请求完全不变 | 停用插件并重启后回到原组件；不需要还原安装文件 |
| B：通过摘要扩展点自行调用模型服务 | 扩展接口公开，但要自行承担请求转换、凭据、流式解析、重试及中断等代码 | 不复制原适配器，但容易遗漏工具历史、图片及错误语义；测试和维护面更大 | 可停用，但同样需要标准模式配置接入 |

不选“全局关闭思考”或“增加摘要专用模型接入”，因为不符合已确认需求。不把现有安装文件覆盖脚本作为发布方案。

## 推荐方案的组成

### 1. 模型请求适配

以官方发布的 llm-pi-ai 对应版本为源，保存来源、版本、许可证、原始文件摘要及可审阅的最小差异。制品内携带派生组件，不在用户安装目录现场改代码，也不用全局替换网络请求或运行时改私有方法。

插件启用时停用应用层原 llm-pi-ai 组件，装载派生组件，继续读取原来的 llm-pi-ai 设置及凭据。注册的服务商和模型标识保持不变；不能同时注册两个组件争用相同接入。

只在请求用途为 compaction、服务商和模型精确命中目标、协议为 openai-completions 时，用模型描述的副本设置 chat_template_kwargs.enable_thinking=false。需同时满足原 SDK 的思考格式和能力条件，保证参数真正出现在发出的请求中；共享模型对象保持不变。普通聊天、非目标模型和其他用途走原代码。

首版默认目标为现有 qwen38 / Qwen3.8-27B。公开说明服务商标识只是用户配置的名称，不能仅凭显示名称判断模型。其他接入名称须明确配置对应目标；适配目标与压缩上限策略必须保持一致，不得一边生效、一边遗漏。

### 2. 原生压缩设置

保留原生 BasicCompactionEngine、自动触发条件、保留近期内容的规则、取消和安全替换机制。只给精确目标增加 maxTokens=16384 的 modelPolicies，不提高其他模型的摘要上限，不强行改用户明确设置的自动压缩开关。

插件携带固定版本标准模式配置及显示信息，保持 standard 标识和其余内容不变。通过原生模式目录配置或薄包装，将插件的 standard 放在原内置目录前，其他模式仍从原目录提供。该标准配置来自官方版本，仅有压缩策略差异；逐项比较工具、权限和提示词，不能悄悄增删能力。

旧对话在原进程中已有驻留组件，因此完成安装后需要重启 DSH，再打开原对话；不迁移或重写旧对话日志，不新建对话替代验收。

自定义配置需要保留：若已有非默认适配器配置、标准模式改动或自定义模式目录，安装前对比并合并已授权部分；遇到不能自动保留的差异，明确指出具体冲突，不覆盖。

### 3. 安装和停用

提供普通 DSH 插件包和 GitHub 发布附件，中文说明以现有 Windows 浏览器入口为准。不增加服务账号、代理、独立运行环境或模型入口。

插件通过官方包管理入口加入 web 配置。安装材料不得写入真实服务地址或凭据；读取目标配置仅发生在用户本机。

加载前校验实际相关包版本。首版仅宣称通过验收的版本组合；不兼容时在模型请求前给出明确错误，不能显示启用却无效。

## 数据流

1. 原对话达到压缩条件，或用户使用原生手动压缩。
2. 原生压缩组件选取较早内容，带着目标的 16384 摘要上限发出摘要请求。
3. 插件只对这次 Qwen 摘要请求关闭思考，使用原服务地址和凭据发送。
4. 原生组件检查摘要完整、非空且确实缩小上下文，再安全写入压缩结果。
5. 继续普通聊天；请求中的思考行为不受本次压缩设置影响。

## 错误处理

- 摘要为空、被截断、请求被取消或服务报错：沿用原生失败处理，不以部分摘要替换历史，也不拿思考文本凑摘要。
- 服务忽略关闭思考参数：真实验收视为失败，不能靠隐藏界面上的思考内容冒充适配成功。
- 压缩后关键事实缺失：视为内容验收失败，回查摘要生成，不以占用率下降作为唯一成功标准。
- 不把 16384 当作所有上下文长度和部署的保证；验证实际服务是否接受该输出预算及完整请求。
- 插件重复加载、原组件未停用、配置目标不一致、版本冲突：报清楚原因并拒绝半生效状态。
- 安装失败：恢复本次配置变更，不动用户原对话和凭据。

## 验证策略

1. 以不带本机旧补丁的目标 DSH 版本加载实际打包产物，确认是插件产生效果。
2. 检查实际发出的 HTTP 请求，覆盖目标摘要、目标普通聊天、非目标模型和并发调用，验证字段、输出上限和原对象不变。
3. 用合成长对话触发真实自动压缩，并单独执行原生手动压缩；随后继续问答，逐项核对预埋目标、数字、纠正、约束和待办。
4. 用可控故障服务核对空摘要、截断、取消、服务错误与历史保护；通过原生事件及结果检查，不能只断言模拟函数被调用。
5. 停用插件，核对模型列表、标准模式、原接入和普通聊天恢复；安装与回滚都检查现有快捷方式入口。
6. 检查打包文件、许可证、中文编码、敏感信息和 GitHub 远端树；公开记录只保留合成材料及无敏感信息的结果。

真实模型调用只使用当前已授权的 Qwen 服务及合成材料，不使用原审计对话作公开测试样本。若没有真实自动、手动压缩及继续对话的成功证据，不发布“已确保正常”的结论。

## 本机已有修补的迁移

先把涉及的当前安装文件和配置备份到统一 BackUp 目录并核对文件摘要。将当前文件与原版备份及官方包比较，只撤销本项目先前的手工修补，保留用户后来改动的默认模型、其他插件和配置。

在独立验收成功后再迁移现有使用环境；重启前确认没有正在执行的任务。迁移失败可以恢复刚才备份的可用修补状态。插件停用后的原生行为与“恢复先前可用修补状态”是两种回滚，不混为一谈。

## 设计决策树

- 已确认目标：现有标准模式和模型接入中的自动、手动压缩可用。
  - 触发、历史保留、摘要安全替换：复用原生机制。
  - 普通聊天：不改变。
  - 公开资料：只含源码及合成测试，不含本机资料。
  - 已采用方案 A 的最小派生插件，未重写摘要请求。
    - 推荐 A：最接近已经有效的改动，少承担一套模型通信代码。
  - 版本与制品验证：先验证当前固定版本，再决定是否扩大兼容范围。

目前没有需要单独 ADR 的难以逆转决策；来源与取舍已记录于本方案。
