# DSH 与 Qwen3.8 上下文压缩插件需求

状态：用户于 2026-09-09 回复“ok”确认需求，随后明确要求立即编写插件、不再停下等待；按推荐方案连续完成实施、验收及已授权的 GitHub 发布。

## 背景与问题

用户要求将本机已有效的上下文压缩修补做成 DSH 插件，并公开发布到 GitHub；核心目标是确保 Qwen3.8 与 DSH 能正常压缩上下文。

现有证据：本机 DSH 0.1.2-rc.1 的压缩功能已开启，但多次摘要生成达到输出上限后被拒绝；调整压缩专用思考参数及输出上限后，一次真实手动压缩成功。该结果只能证明本机修补有效，不能替代插件验收，也不能证明任意模型部署都兼容。

## 用户与使用场景

- Windows 上使用 DSH 与 Qwen3.8 的用户。
- 继续使用现有模型接入和标准模式，包括已有对话。
- 长对话达到压力阈值时自动压缩；用户执行原生手动压缩时使用同一适配逻辑。

## 已确认范围

1. 制作可安装、可停用的 DSH 插件，适配 Qwen3.8 的上下文压缩。
2. 自动压缩与原生手动压缩均须实际可用。
3. 不增加模型入口，不要求换标准模式，不改变普通聊天的思考设置。
4. 摘要生成须有足够输出空间，并控制无效思考输出；使用已有模型服务，不增加新的服务账号或密钥。
5. 压缩后能继续使用先前的任务目标、重要约束、已确认事实和待办事项。
6. GitHub 公开交付源码、中文使用说明、安装与停用方法、兼容版本说明和验证材料。

## 明确不做

- 不制作通用模型管理器、代理服务器或额外聊天界面。
- 不修改模型权重，不全局关闭思考，不为普通请求套用压缩设置。
- 不把本机安装文件替换脚本冒充插件；优先使用 DSH 的插件扩展能力。
- 不向公开仓库放入真实对话、业务资料、服务地址、密钥、凭据、本机配置或完整故障日志。
- 不顺带处理其他插件、审计业务或其他模型的兼容问题。
- 不承诺未测试的 DSH 版本或所有 Qwen3.8 部署方式都适用。

## 验收标准

1. 干净的目标版本 DSH 环境可安装和加载插件，不依赖先前的本机源码补丁。
2. 合成长对话达到原生触发条件后，发生自动压缩、实际生成完整摘要并降低上下文占用；随后能继续对话。
3. 同一环境执行原生手动压缩，也能产生有效摘要并继续对话。
4. 在压缩前埋入可核对的目标、数值、约束、纠正和待办；压缩后逐项核对这些关键内容。
5. 请求级检查确认压缩使用目标设置，普通聊天及非目标模型不受影响。
6. 取消、摘要截断、空摘要、服务报错时不得写入损坏摘要；未成功替换前保留原历史，取消能够生效。
7. 停用插件后恢复原生行为，不留下重复接入；迁移本机已有补丁须备份并核对。
8. 发布前检查实际打包清单、敏感信息及公开仓库文件树；验证结果须区分真实模型测试和可重复的离线检查。

## 约束与风险

- 模型服务必须支持所采用的思考控制方式；模型名称相同不代表服务行为完全一致。
- 网络中断、服务不可用与输出内容质量不能靠插件绝对保证；错误应清楚可见，原历史应受到保护。
- 不能只检查插件加载或参数对象，必须检查实际发出的请求和压缩后的对话。
- 本机先前的手工修补可能掩盖插件缺陷；验收须排除这类干扰。
- 不支持的 DSH 版本要明确提示，不能静默失效。
